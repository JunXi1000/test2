================================================================================
                        前端代码优化建议报告
================================================================================

项目：xmszjx-front (Vue 3 + Vite + Element Plus + Tailwind CSS)
日期：2026-03-28

================================================================================
一、重复代码和死代码（高优先级）
================================================================================

1. 存在三套 HTTP 请求封装，互相冲突
--------------------------------------------------------------------------------
项目中同时存在三个 HTTP 请求模块，新旧系统并存：

  - src/api/http.ts        — 新的 API 层（被 src/api/modules/*.ts 使用）
  - src/utils/http.js      — 旧的请求封装（使用 ElLoading 全屏加载，所有请求自动重试）
  - src/utils/request.js   — 又一个旧的请求封装（也有重试、加载动画逻辑）

http.js 和 request.js 功能高度重复，且都引用了旧的路由和 ElMessage。
新模块 api/http.ts 才是当前使用的主力。

【建议】确认 utils/http.js 和 utils/request.js 是否还有页面在用
（src/views/ 下的旧页面可能还在引用）。如果旧页面已废弃，应一并清除。


2. 两套验证工具重复
--------------------------------------------------------------------------------
  - src/utils/validate.js   — 包含字符串、数字、数组等校验
  - src/utils/validator.js  — 包含表单验证规则

两者都有手机号、邮箱、密码、身份证等正则验证，大量重复。
src/utils/tools.js 里也内嵌了 rules（必填、邮箱、密码等验证规则），
是第三份重复。

【建议】统一为一个验证模块。


3. 防抖/节流函数重复定义了三次
--------------------------------------------------------------------------------
  - src/utils/tools.js          — debounce() / throttle()
  - src/utils/performance.js    — optimization.debounce() / optimization.throttle()
  - 实际使用中 Home.vue 直接从 lodash-es 引入 debounce

【建议】统一使用 lodash-es 的 debounce/throttle，或使用 @vueuse/core 的
useDebounceFn/useThrottleFn，删除手写重复实现。


4. 新旧页面系统并存
--------------------------------------------------------------------------------
项目同时存在两套页面系统：
  - src/pages/  — 新的页面（Login、Home、ProductDetail 等）
  - src/views/  — 旧的页面（Login.vue、Register.vue、admin/ 管理后台等）

旧的 src/views/ 包含 admin/ProductManage.vue、admin/UserManage.vue、
front/ShoppingCart.vue 等完整管理后台和前台页面，但当前路由
(src/router/index.ts) 没有引用 views/ 下的任何页面。

【建议】如果旧页面已经完全迁移，应删除整个 src/views/ 目录和关联的
旧工具（utils/http.js, utils/request.js, utils/tools.js 等），减少构建体积。


================================================================================
二、Bundle Size 优化（高优先级）
================================================================================

5. 同时引入 lodash 和 lodash-es
--------------------------------------------------------------------------------
  "lodash": "^4.17.21",
  "lodash-es": "^4.17.23",

lodash 是 CommonJS 格式，不支持 tree-shaking，会被整体打包。
lodash-es 才是 ESM 版本。

【建议】移除 lodash 依赖，统一使用 lodash-es。
如果有旧代码引用 lodash，改为从 lodash-es 引入。


6. 两套图标库并存
--------------------------------------------------------------------------------
  "@ant-design/icons-vue": "^7.0.1",
  "@element-plus/icons-vue": "^2.3.1",
  "lucide-vue-next": "^0.575.0",

新页面使用 lucide-vue-next（tree-shakable、体积小），但同时还保留了
@ant-design/icons-vue 和 @element-plus/icons-vue。
如果旧页面已废弃，这两个包完全多余。

【建议】确认后移除不再使用的图标库。


7. 两套富文本编辑器
--------------------------------------------------------------------------------
  "@wangeditor/editor": "^5.1.14",
  "@wangeditor/editor-for-vue": "^5.1.12",
  "@kangc/v-md-editor": "^2.3.18",

wangEditor 和 v-md-editor 都是较重的包。
如果只有旧管理后台用到，随旧页面一起清除即可。


8. Mock 数据硬编码在生产代码中
--------------------------------------------------------------------------------
src/api/modules/product.ts 中包含 140 条 mock 商品数据
（约 50 多行的 BASE_PRODUCTS 数组，加上循环生成），
这些数据在生产环境中会被打进 bundle。

【建议】将 mock 数据移到单独文件，通过 import() 动态导入，
或使用 Vite 的条件构建 (import.meta.env.DEV) 确保生产包不含 mock 数据。


================================================================================
三、性能优化（中优先级）
================================================================================

9. DefaultLayout.vue 中 ChatWidget 未做懒加载
--------------------------------------------------------------------------------
ChatWidget 是浮动聊天窗，大多数时候用户不会立即使用，
但它被同步引入到布局中：

  import ChatWidget from '@/components/ui/chat/ChatWidget.vue'

【建议】改为 defineAsyncComponent 懒加载：

  const ChatWidget = defineAsyncComponent(
    () => import('@/components/ui/chat/ChatWidget.vue')
  )


10. Home.vue 无限滚动没有使用节流
--------------------------------------------------------------------------------
scroll 事件触发频率极高，虽然内部有条件守卫，但每次滚动都要执行
DOM 读取 (window.scrollY, window.innerHeight,
document.documentElement.scrollHeight)。

【建议】使用 @vueuse/core 的 useIntersectionObserver 监听底部哨兵元素，
或对 scroll handler 添加 throttle。


11. ProductDetail.vue 文件过大（1300+ 行）
--------------------------------------------------------------------------------
这个组件承担了太多职责：商品展示、图片画廊、颜色/尺码选择、
评论系统（CRUD、排序、过滤、图片上传、分页）、tab 切换联动滚动。

【建议】拆分为子组件：
  - ProductGallery.vue   — 图片画廊 + 缩略图
  - ProductConfig.vue    — 颜色/尺码/数量选择
  - ProductReviews.vue   — 评论系统
  - ProductTabs.vue      — Tab 切换


12. index.html 末尾有空的 <script> 标签
--------------------------------------------------------------------------------
位于 </body> 之后，属于无效 HTML。

【建议】删除。


13. Vite 构建缺少 gzip/brotli 压缩插件
--------------------------------------------------------------------------------
vite.config.ts 没有配置压缩插件。

【建议】添加 vite-plugin-compression 以生成 .gz / .br 文件，
配合 Nginx 的 gzip_static 进一步减小传输体积。


================================================================================
四、代码质量与架构（中优先级）
================================================================================

14. utils/ 下大量工具文件可能是死代码
--------------------------------------------------------------------------------
src/utils/ 下有 27 个文件，其中很多像是模板生成的"全家桶"：

  animation.js, browser.js, cache.js, converter.js, crypto.js,
  device.js, error.js, eventBus.js, feedback.js, formatter.js,
  interaction.js, logger.js, media.js, message.js, performance.js,
  router.js, theme.js, ui.js, ux.js

很多可能从未被实际引用。

【建议】全局搜索每个文件的 import 引用，删除无人使用的文件。
Vite tree-shaking 虽然能跳过未引用的导出，但如果文件顶层有副作用代码
（如 performance.js 中的 restoreSessionBudget() 在模块加载时立即执行），
仍会被打包。


15. utils/request.js 中的重试逻辑有 Bug
--------------------------------------------------------------------------------
retryConfig.currentRetry 是模块级共享变量，永远不会重置，
所以只有最初的 2 次超时重试有效，之后所有请求都不会再重试。


16. ui-optimization.css 与 Tailwind CSS 变量冲突
--------------------------------------------------------------------------------
src/assets/css/ui-optimization.css 定义了自己的一套 CSS 变量
（--primary-color, --spacing-1 等）和组件类（.ui-card, .ui-button），
与 tailwind.css 中定义的主题变量（--primary, --background 等）
完全独立、互不关联。

【建议】如果新页面全部使用 Tailwind + 自定义 CSS 变量体系，
应移除 ui-optimization.css。


================================================================================
五、构建配置优化（低优先级）
================================================================================

17. Vite 构建未配置 cssCodeSplit
--------------------------------------------------------------------------------
默认行为已经不错，但可以显式配置以确保每个异步 chunk 的 CSS 独立加载。


18. autoprefixer 可能与 @tailwindcss/postcss 功能重复
--------------------------------------------------------------------------------
Tailwind CSS v4 的 @tailwindcss/postcss 插件已内置前缀处理，
再单独引入 autoprefixer 可能是多余的。
